## Результат для пользователя

Каждый PR репозитория получает независимое автоматическое ревью read-only сессией закреплённого бесплатного CLI на событиях `pull_request: opened, synchronize, reopened`: замечания публикует отдельный шаг workflow без модели, ревью фиксирует проверенную версию PR. Ручные команды агента на PR ограничены бюджетом из 3 допущенных запусков. Отдельная браузерная job без секрета модели проверяет точную версию PR `head.sha` и сохраняет отчёт и диагностику в Actions artifact. Отказы и исчерпание лимита объясняются no-model reporter'ом с указанием «нужен человек».

## Критерии приёмки

- AC-01: Workflow `.github/workflows/opencode-pr-review.yml` обрабатывает только `pull_request` с типами `opened, synchronize, reopened`; `pull_request_target` не используется. Job допуска работает до checkout и секрета модели: доверенные авторы — `skaffman41` (тип User) и бот нашего OpenCode App (`opencode-agent[bot]`, тип Bot — PR приложения обязателен к проверке, боты не исключаются целиком), head и base только в `skaffman41/ai-for-developers-project-387`; fork и недоверенные авторы отклоняются без секрета.
- AC-02: Ревью выполняет отдельная read-only сессия обычного CLI закреплённого runtime (агент чтения: только read/glob/skill; shell, запись и делегирование запрещены), не сессия разработчика. В контекст ревью входят REVIEW.md с критериями календаря, тело PR (исходный issue, спецификация, тикеты, согласование), diff PR, состояние CI и уже разобранные замечания PR. Модель та же закреплённая бесплатная без fallback.
- AC-03: Публикация замечаний — отдельный шаг workflow без вызова модели; модель не имеет инструментов правки кода и публикации и не одобряет PR (review-approve нет). Каждый дефект содержит файл, строку, условия возникновения и последствия; при отсутствии дефектов ревью сообщает это честно. Опубликованный комментарий фиксирует проверенный head SHA.
- AC-04: Concurrency-группа на PR отменяет устаревшее ревью того же PR (`cancel-in-progress: true`); повторное ревью одной и той же версии head SHA не создаётся (состояние — история Actions, считанная API до модели); тайм-аут ревью — 30 минут. Авторевью не расходует ручной бюджет и не создаёт циклов исправлений.
- AC-05: Бюджет: суммарно 3 допущенных ручных запуска на PR по `issue_comment` и `pull_request_review_comment`, включая read-only и publish, отмены, тайм-ауты и каждый `run_attempt` при Re-run. Проверка выполняется кодом до раскрытия секрета модели, без гонок (общая очередь на PR без отмены работающего). Источник состояния — история Actions (маркер в run-name), которую токен агента не может менять; комментарии и метки источником не являются.
- AC-06: Отдельный no-model reporter сообщает `limit_exhausted`, `timeout`, `agent_failed` или `infra`, последний известный SHA, ссылку на run и «нужен человек»; reporter выполняется после остановки агента со своим собственным тайм-аутом и не вызывает модель.
- AC-07: Добавлен шаблон PR с обязательными разделами: исходный issue, спецификация, тикеты, согласование, проверки с SHA и ссылками, риск по последствиям, откат кода и данных. README и docs/agents обновлены: события ревью, доверенный допуск, бюджет, reporter, браузерная job и границы запусков.
- AC-08: Отдельная браузерная job без секрета модели: checkout точного PR `head.sha`, сохранение `git rev-parse HEAD`, отчёт о прогоне и trace либо скриншот успешного прогона публикуются в Actions artifact; после push (synchronize) проверяется новая версия. Обычный CI с тестами и линтером сохраняется (hexlet-check и app-check не упраздняются).
- AC-09: Добавлены тесты допуска, бюджета и отказов (YAML и логика authorize/budget/reporter с моками API). `.github/workflows/hexlet-check.yml` побайтово не меняется; закреплённые версии action, runtime, модели и mise сохраняются; полный `mise run check` зелёный.

## Testing Decisions

- Новые автотесты прямо поручены владельцем: тесты допуска/бюджета/отказов в стиле существующего `tests/release-workflow.test.ts` — разбор YAML и исполнение github-script логики с моками REST API.
- Эффективные инструменты ревью-режима проверяются локально пробами `opencode debug agent` (разрешённые проходят; запись, shell, task и публикация — отказ) и `verify`-проверкой конфигурации до вызова модели.
- Существенные изменения проходят две независимые оси `review-standards`/`review-spec` до коммита; документация проверяется ссылками, путями и `git diff --check`.
- Обязательный полный `mise run check` с timeout не меньше 600000 мс.
- Живая приёмка (реальные события PR, комментарий ревью, исчерпание лимита, artifact браузерной job) после merge — отдельное решение владельца по образцу #6; этот PR фиксирует только локально проверенное.
