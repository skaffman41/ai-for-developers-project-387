## Результат

1. `.github/workflows/opencode.yml`:
   - детерминированный `run-name` с маркером номера Issue/PR (без содержимого комментария), например `opencode #<number> <mode>`;
   - в job `authorize` до раскрытия `OPENCODE_API_KEY`: подсчёт через GitHub API истории запусков этого workflow, относящихся к текущему номеру (маркер run-name), по `issue_comment` и `pull_request_review_comment`; учитываются допущенные read-only и publish запуски, отмены, тайм-ауты и каждый `run_attempt` (Re-run); если уже израсходовано 3 допущенных запуска — явный отказ `limit_exhausted` без модели, без checkout и без секрета;
   - гонки исключены общей concurrency-группой на номер (`cancel-in-progress: false`): счёт читается, когда предыдущий запуск уже завершился;
   - источник состояния — только история Actions; токен задания агента не получает прав записи истории Actions; комментарии и метки источником не являются.
2. Отдельный no-model reporter (job без checkout и секрета модели, свой тайм-аут, выполняется после остановки агента): публикует один комментарий/уведомление при `limit_exhausted`, `timeout`, `agent_failed` или инфраструктурной ошибке с причиной, последним известным SHA, ссылкой на run и «нужен человек»; не публикует ничего при успешном ответе агента и при обычных пропусках (бот/не-владелец/без команды).
3. Тесты бюджета и отказов в стиле `tests/release-workflow.test.ts`: подсчёт запусков и попыток по истории Actions, отказ на 4-м запросе, допущение 3-го, отчёт reporter по каждому классу отказа и молчание при пропусках.

## Критерии

- Первый, второй и третий допущенные ручные запуски PR проходят; четвёртый и последующие отклоняются до модели с понятным сообщением; ручные команды на Issue бюджетом PR не затрагиваются (счёт по номеру PR).
- Каждый Re-run и тайм-аут учитываются бюджетом; отмены учитываются.
- Авторевью (`opencode-pr-review.yml`) не расходует ручной бюджет.
- Токен агента не может изменить источник состояния (нет прав на Actions/историю).
- Reporter не вызывает модель и не мешает успешным ответам; закреплённые версии и `hexlet-check.yml` не меняются; полный `mise run check` зелёный.

## Testing Decisions

- Новые автотесты поручены; логика подсчёта и классификации отказов исполняется в тестах с моками API списков runs.
- Локально: YAML-разбор, форматирование, `git diff --check`, полный `mise run check`, две независимые оси ревью; живая проверка лимита — отдельное решение владельца после merge.
