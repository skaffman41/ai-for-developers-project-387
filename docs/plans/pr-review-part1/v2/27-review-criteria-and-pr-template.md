Критерии приёмки: AC-07 (REVIEW.md и шаблон PR), AC-09 (только в части сохранения hexlet-check и закреплённых версий).

## Результат

1. Файл `REVIEW.md` в корне репозитория: чек-лист независимого ревью PR с критериями календаря. Разделы: неизменность календарной функциональности и её пользовательских гарантий (правила доступности, зона Europe/Moscow, попытки/повторы, целостность SQLite и схема версии 3), правила контракта TypeSpec и производных (`mise run api:generate`, ручное изменение производных запрещено), неизменяемость `.github/workflows/hexlet-check.yml`, требования workflow-изменений (допуск до секретов, закреплённые версии, отсутствие расширения прав), требования к коммитам и документации. Для каждого пункта — что проверять и что считать дефектом.
2. Файл `.github/pull_request_template.md`: обязательные разделы — исходный issue, спецификация, тикеты, согласование (ссылка на разрешение владельца), проверки (команды, SHA, ссылки на runs), риск по последствиям, откат кода и данных.

## Критерии

- REVIEW.md фиксирует критерии календаря, контракта, agent-контура и workflow-безопасности; каждый критерий проверяем без доступа к живому GitHub.
- Шаблон PR содержит все семь разделов из AC-07 и короткие подсказки, что в каждом писать.
- Оба файла проходят Prettier/линтер; ссылки и пути в них корректны; `git diff --check` чистый.
- Функциональность календаря не меняется.

## Testing Decisions

- Автотест не нужен: проверка — существующие `mise run lint`, `format:check`, `typecheck` и разбор ссылок/путей; шаблон и критерии проверяются самим ревью-графом позже.
- Документация проверяется независимой самопроверкой ссылок и `git diff --check`.
