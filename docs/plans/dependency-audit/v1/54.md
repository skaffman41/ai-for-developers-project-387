## Parent

Спецификация [#53 «Регулярный аудит зависимостей GitHub-агентом — шаг 5 Hexlet»](https://github.com/skaffman41/ai-for-developers-project-387/issues/53). Граф из трёх последовательных задач согласован владельцем в текущем обсуждении ответом «Согласовываем».

## What to build

Владелец репозитория получает работающий путь «запуск аудита → полный отчёт зависимостей → анализ GitHub-агентом → постоянный журнал и артефакт». Один workflow запускается ежедневно в 06:17 по Москве и вручную из main, не требует комментария /oc и использует существующую бесплатную модель. Результат различает чистый отчёт, находки ниже порога, известные/новые high или critical и технический отказ.

Эта задача реализует самостоятельный полезный сценарий отчёта и журнала. Автоматическое создание отдельных задач по находкам и повтор сохранённых данных добавляются следующим тикетом; живая приёмка после интеграции относится к третьему. Наличие готового workflow в рабочей ветке не объявляется завершением AC1/AC11 родителя.

## Acceptance criteria

- [ ] В одном workflow заданы schedule и workflow_dispatch, ежедневный запуск 06:17 Europe/Moscow, ограничение рабочего ref веткой main, тайм-аут аудита 20 минут и общая concurrency для обоих входов. Выполняется один аудит одновременно; новый запуск не отменяет работающий.
- [ ] npm audit получает полный JSON по закреплённому дереву зависимостей всех workspaces, включая devDependencies. Сохранение отчёта не отфильтровывает low/moderate. Автоматического исправления зависимостей нет.
- [ ] Отчёт и результат сохраняют репозиторий, исследованный SHA, идентичность lockfile/отчёта, тип данных и ссылку на запуск. Отчёты находятся вне рабочего дерева либо в игнорируемом каталоге и не попадают в коммит.
- [ ] Агент получает явный фиксированный prompt, отчёт и контекст существующих открытых/закрытых Issues с пагинацией. Он сохраняет содержательное заключение и ограничения применимости, не выдавая advisory за подтверждённую уязвимость календаря. Контекст комментария или PR для запуска не нужен.
- [ ] Используются закреплённые OpenCode CLI 1.19.6, модель opencode/deepseek-v4.1-flash-free и существующая подготовка Matt Pocock Skills. Проверяется фактически установленная версия CLI. Нет платного fallback.
- [ ] Права и доступные операции ограничены чтением проекта/Issues и публикацией результатов аудита в целевом репозитории. Аудит не получает возможностей изменения кода, создания PR, merge или изменения истории Actions. Существующие режимы GitHub-агента сохраняют свои границы.
- [ ] На процесс существует один служебный Issue журнала. Он создаётся при необходимости и далее обновляется в теле без одинаковых комментариев. В нём есть содержательный вывод, SHA, происхождение/идентичность данных, ссылка на Actions run и ссылки на известные задачи; одной временной ссылки недостаточно.
- [ ] Различаются полностью чистый отчёт, отсутствие подходящих high/critical, известные high/critical и новые кандидаты. На этом этапе новые кандидаты отражаются в журнале, создание отдельных задач оставлено следующему тикету.
- [ ] Ненулевой exit npm audit с валидными advisories не считается технической ошибкой. Недоступный/невалидный отчёт, ошибка/тайм-аут модели и отказ публикации не превращаются в «проблем нет» или «исправлено». Результат ошибки доступен в возможных при отказе границах — журнале и/или диагностике запуска; для завершения публикации предусмотрено ограниченное время после остановки анализа.
- [ ] Исходный JSON, результат анализа и доступная диагностика сохраняются артефактами; срок хранения описан. Повторное создание журнала исключено, в том числе после частично успешной публикации.
- [ ] В руководстве проекта описаны доступный сценарий, расписание, ручной запуск, права, статусы результата, журнал и место хранения отчётов; живая приёмка обозначена как предстоящая, без выдуманных ссылок на успешный запуск.
- [ ] Согласованные автоматические проверки проходят; необходимое независимое Standards/Spec review и полный mise run check успешны. Календарь, контракт, закреплённые зависимости приложения и обязательный workflow Hexlet не изменены.

## Testing Decisions

Используется разрешение новых проверок аудита из Testing Decisions #53. Основной шов — весь audit-runner на управляемых входах и внешних границах: заданный npm-отчёт и inventory Issues → анализ → операции журнала и сохранённые результаты. Реальные advisories, доступность registry и бесплатной модели не должны определять результат автоматического теста.

Проверить чистый отчёт, разные уровни серьёзности и devDependencies, ожидаемый ненулевой exit при advisories, невалидные данные/сбой npm, отсутствие конфигурации модели, ошибочный ответ/ошибку/тайм-аут модели, отказ публикации, один журнал и обновление его тела без дублей, происхождение данных, обе точки входа, main/права/pins/timeout/concurrency и артефакты. Переиспользовать существующие Vitest-подходы к subprocess и подготовке GitHub-агента; не добавлять календарный E2E-шов для аудита.

## Completion boundary

Живые прогоны и фактическая включённость workflow в main подтверждаются третьим тикетом; Issue остаётся открытым до интеграции по правилам проекта.
