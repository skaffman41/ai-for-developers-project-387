## Parent

Спецификация [#53 «Регулярный аудит зависимостей GitHub-агентом — шаг 5 Hexlet»](https://github.com/skaffman41/ai-for-developers-project-387/issues/53). Третья задача согласованного линейного графа — итоговая живая приёмка всех обязательных требований шага 5.

## What to build

Владелец и наставник получают проверяемые доказательства работающего периодического GitHub-агента: успешный ручной запуск из main сохранил отчёт, агент опубликовал содержательный вывод и создал отдельную задачу, а повтор тех же данных не создал дубль. Руководство проекта содержит прямые ссылки, результаты и личные выводы владельца.

Живая часть начинается после отдельно разрешённых публикации и интеграции предыдущих результатов в main. Этот тикет не является автоматическим разрешением push, PR или merge. Локальная готовность реализации без этих событий не закрывает приёмку.

## Acceptance criteria

- [ ] Подтверждено, что один и тот же audit-workflow находится в main, включён и содержит schedule и workflow_dispatch. Проверены 06:17 Europe/Moscow, частота не выше ежедневной, тайм-аут 20 минут, общая concurrency, main, prompt и права.
- [ ] Подтверждён успешный ручной запуск из main с фактическим вызовом закреплённой бесплатной модели, исходным отчётом, доступным содержательным выводом и единственным постоянным журналом. Сохранены URL запуска, проверенный SHA, идентичность и тип данных, ссылки на журнал и артефакт.
- [ ] Агент автоматически создал отдельный Issue по подходящей новой реальной находке; либо при отсутствии подходящей находки сценарий продемонстрирован на явно учебном отчёте и учебном Issue. Задача содержит проблему, предлагаемое действие и связь с отчётом/проектом/run. Полный отчёт без отдельной задачи не считается выполнением этого критерия.
- [ ] Выполнен второй успешный ручной запуск того же workflow из main с теми же исходными байтами. Сверены идентичность отчёта/находки, существующая задача, журнал и комментарии; новой задачи по той же находке и одинакового комментария нет. Сохранена прямая ссылка на повторный run.
- [ ] Проверено, что учебная демонстрация не выдаётся за доказанный дефект календаря и не смешивается с реальными данными. Повтор старого отчёта не выдаётся за свежую проверку registry/нового SHA.
- [ ] Открыты и проверены артефакт и постоянный журнал: исходные данные, результат, SHA и ссылки согласованы. Содержательный вывод остаётся в Issue, а не только по временной ссылке. Срок хранения артефакта указан; отчёты и журналы процессов не попали в коммиты.
- [ ] В руководстве проекта есть описание workflow, расписания, ручного запуска и повторной обработки, отчёта и журнала, прав/границ, high/critical и лимита одной задачи, ошибок/ограничений, результатов и прямые ссылки на оба прогона, задачу и журнал.
- [ ] С владельцем после живых прогонов согласован текст его личных выводов: что потребовало уточнений и что было изменено в настройках либо постановке задачи. Текст опубликован в руководстве либо связанном из него документе; мнение владельца не выдумано агентом.
- [ ] По каждому AC1–AC12 #53 есть отдельный итог с доказательствами. Подтверждены успешные обязательные проверки и необходимое независимое Standards/Spec review итоговой реализации; при изменении проверенного дерева выполнены применимые повторные проверки. Workflow Hexlet сохранён.
- [ ] Итоговый отчёт явно отличает завершённую живую приёмку от локальной готовности. Фактического ночного запуска для сдачи не требуется. Кнопки завершения и сдачи проекта на Hexlet оставлены владельцу.

## Testing Decisions

Главный шов этой задачи — настоящий GitHub Actions из main и наблюдаемые внешние результаты: report/model/run → журнал и отдельный Issue → повтор тех же данных без дублей. Результат устанавливается по журналам Actions, сохранённым исходным данным и состоянию Issues, а не по одному сообщению модели.

Согласованные автоматические проверки и полный mise run check предыдущих задач служат дополнительными доказательствами и не заменяют два живых запуска. Если проверяемое дерево изменилось, повторить затронутые проверки по проектному workflow. Для документации проверить фактические утверждения, ссылки, форматирование и чистоту diff; отчёты в Git не добавлять. Дополнительное расширение о повторном появлении исправленной проблемы не требуется.
