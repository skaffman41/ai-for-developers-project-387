## What to build

Гость на шаге контактов видит необязательное многострочное поле «Тема разговора». Введённая тема сохраняется вместе с бронированием: она показывается в подтверждении бронирования у гостя и рядом с записью в списке бронирований владельца во всех периодах (предстоящие, прошедшие, все). Бронирования без темы — и новые, и созданные до изменения — выглядят и работают как раньше, без пустых заглушек. Обычная запись без темы проходит весь привычный флоу — выбор слота, контакты, подтверждение, список владельца — без новых обязательных шагов. Бронирование уже занятого интервала возвращает обычный отказ конфликта времени независимо от того, заполнена тема или нет.

Технический объём: термин «Тема разговора» фиксируется в глоссарии; поле `topic` добавляется в TypeSpec-контракт (модель бронирования, черновик попытки, вход создания бронирования) со штатной перегенерацией производных (ADR 0004, ADR 0005); одна транзакционная миграция добавляет NULL-колонку темы в таблицу бронирований с сохранением всех существующих данных (ADR 0003); тема пробрасывается в модель, подтверждённый ответ и список владельца; в форме гостя — многострочное поле с человекочитаемым сообщением об ошибке.

## Acceptance criteria

- [ ] Гость на шаге контактов видит необязательное многострочное поле «Тема разговора»; пробелы по краям убираются, переносы строк разрешены, пустая после обрезки считается отсутствующей.
- [ ] Тема длиннее 200 символов после нормализации даёт понятное сообщение об ошибке без потери остальной формы; длина проверяется после нормализации.
- [ ] Бронирование с темой сохраняет её: подтверждение гостя и запись в списке владельца показывают тему целиком, включая переносы, во всех периодах списка; у прошедших бронирований тема тоже видна; тема читается вспомогательными технологиями как обычный текст записи.
- [ ] Бронирование без темы не блокируется и не получает новых обязательных шагов: полный флоу записи без темы не отличается от текущего поведения; старые бронирования без темы отображаются без пустых заглушек.
- [ ] Бронирование занятого интервала возвращает обычный отказ конфликта времени независимо от того, заполнена тема или нет.
- [ ] Термин «Тема разговора» зафиксирован в глоссарии; контракт меняется только в TypeSpec со штатной перегенерацией производных; миграция транзакционная, данные сохраняются, ожидаемые схемы контролируются для всех поддерживаемых версий.
- [ ] HTTP/Vitest и Playwright проверки основного и негативного сценариев добавлены на существующих швах; проверка существующего сценария без темы проходит до и после изменения.

## Автотесты и приёмка

Добавить HTTP/Vitest и Playwright проверки на существующих швах, как разрешено владельцем: создание с темой и без, нормализация и валидация (пробелы, 200 символов, переносы, пустая после обрезки), показ темы в подтверждении и списке владельца по периодам, открытие БД прошлой версии с сохранёнными бронированиями, конфликт времени с темой и без неё, обычная запись без темы. Сначала воспроизвести отказ при отсутствии нового поведения, затем успешный прогон реализации; существующий соседний сценарий без темы должен проходить на обеих версиях. Полный `mise run check` остаётся зелёным, включая независимую сверку сгенерированного контракта.
