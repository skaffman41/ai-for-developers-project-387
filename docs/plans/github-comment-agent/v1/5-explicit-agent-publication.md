## What to build

Добавить к безопасному обычному вызову отдельный сквозной сценарий публикации: точная команда владельца `/oc publish <задача>` допускает изменение файлов для указанной задачи и работу стандартного адаптера, который отправляет рабочую ветку и создаёт либо обновляет PR. Длинная форма `/opencode` эквивалентна. Обычные вопросы сохраняют режим чтения; merge остаётся отдельным действием.

Результат включает согласованные границы разрешения, рабочую конфигурацию обоих режимов и понятные инструкции пользователю. Реальная правка README и PR входят в финальную живую приёмку после отдельно разрешённого включения workflow в основную ветку.

## Acceptance criteria

- [ ] Только отдельная команда `publish` доверенного владельца включает режим изменения и публикации для указанной задачи. Обычная просьба изменить файлы без этой команды не получает разрешения записи.
- [ ] Обе стандартные формы вызова имеют одинаковую семантику; упоминание `publish` в обсуждаемом или цитируемом тексте само по себе не превращает обычный запрос в разрешение публикации.
- [ ] В режиме публикации стандартный адаптер может отправить рабочую ветку и создать PR из Issue либо обновить текущий PR. Полномочия не распространяются на merge, другие репозитории, посторонние задачи или последующие обращения.
- [ ] Разрешение на публикацию не отменяет требования согласованного плана, отдельных коммитов задач, существующих проверок и необходимого ревью. Локальные режимы работы сохраняют прежние правила публикации.
- [ ] Проверены эффективные разрешения обоих режимов в закреплённом runtime: обычный вызов сохраняет ограничения чтения, явная публикация получает необходимые инструменты. Изменение режима не ослабляет фильтры автора, ботов, событий и fork.
- [ ] Для обоих режимов сохраняются бесплатная модель без платного fallback, хранение ключа только в Secrets, `share: false`, стандартная авторизация, 30 минут и общая concurrency на Issue/PR.
- [ ] README и проектные инструкции объясняют отдельную команду публикации, ожидаемый ответ/PR, место просмотра результатов и отдельное решение о merge; актуальные команды разработки сохранены.
- [ ] Существующий workflow Hexlet сохранён побайтно; пройдены соответствующие проверки конфигурации, форматирования и ссылок, полный существующий `mise run check` и необходимое независимое ревью. Новые автотесты не добавлены.
- [ ] Есть отдельный локальный коммит этой задачи и отчёт с SHA и проверками. Подготовлены конкретный пример разрешённой правки README и порядок финальной проверки, без утверждения, что реальный PR уже создан.

## Testing Decisions

Наследуются Testing Decisions спецификации #3. Сравнивается внешнее поведение обычной команды и отдельной команды публикации на границе выбора режима и разрешений runtime. Проверяется отсутствие повышения прав по упоминанию команды в данных. Используются существующие проверки и разовые диагностические команды; новые автотесты не добавляются. Живые push и PR выполняются в финальной задаче с явным разрешением.
