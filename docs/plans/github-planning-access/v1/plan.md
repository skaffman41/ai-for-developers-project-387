# Восстановление публикации планов GitHub-агентом

Источник задачи — [PR #13](https://github.com/skaffman41/ai-for-developers-project-387/pull/13) и [комментарий с исправлениями](https://github.com/skaffman41/ai-for-developers-project-387/pull/13#issuecomment-6953377238). Это исправление инструментария для завершения шага 3, связанное с исходным обращением #12; реализация темы разговора сюда не входит.

## Результат

Режим публикации получает рабочую авторизацию для GitHub Issues и может сохранять новые снимки планов. Доступ к API ограничен трекером текущего репозитория, прежние снимки защищены. Обычный режим чтения и стандартная авторизация App для push/PR сохраняются.

## Критерии

- Workflow передаёт `GH_TOKEN` с правом `issues: write`; подготовка проверяет авторизацию без вывода токена.
- Разрешённые API-вызовы адресованы только Issues `skaffman41/ai-for-developers-project-387`, включая комментарии, native sub-issues и блокирующие связи.
- Каждый существующий файл снимков в bootstrap-checkout получает запрет правки; новые версии можно создавать.
- Сохраняются запреты правки `.git`, файлов окружения и обязательного workflow Hexlet, ограничения режима чтения и делегирования.
- Инструкции соответствуют фактическим разрешениям и порядку аргументов CLI.
- Общий существующий `mise run check`, независимые Standards/Spec и разовые пробы разрешений проходят. После включения проверяется реальная публикация спецификации через комментарий.

## Проверки

Новые автотесты не добавляются. Используются существующий общий check, фактические инструменты закреплённого runtime без вызова модели и живая цепочка «комментарий → Actions → Issue». Проверки не подменяются наличием зелёного ответа с сообщением о блокировке.
