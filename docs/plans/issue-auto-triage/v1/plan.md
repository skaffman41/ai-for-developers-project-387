# Автотриаж новых обращений

Задача: [#14](https://github.com/skaffman41/ai-for-developers-project-387/issues/14). Пользователь поручил полностью завершить шаг 3; [команда владельца](https://github.com/skaffman41/ai-for-developers-project-387/issues/14#issuecomment-6955090457) разрешает выполнение. Облачный запуск 44133077036 остановлен по тайм-ауту; журнал и 34 операции правки сохранены вне репозитория. Итог использует существующий официальный адаптер и режим чтения.

## Решения

- Отдельный workflow на `issues: opened`. Авторизация без checkout и секретов проверяет целевой репозиторий, владельца `skaffman41` типа User, actor/sender и номер Issue. Метка `type:*` при создании означает подготовленную запись и пропуск модели.
- Только допущенный job входит в общую с ручными командами очередь `opencode-<repository>-<issue>`. Один активный job, `cancel-in-progress: false`, тайм-аут 30 минут. Недопущенные события не занимают очередь ответов.
- Тот же закреплённый официальный OpenCode GitHub action, VERSION 1.19.6, бесплатная модель и 38 проверенных скиллов. Инструкция в `with.prompt`: triage по приложению, предварительная классификация, вопросы и следующий шаг; только ответ в текущем Issue. Реализации, PR и автоматических изменений меток нет.
- Подготовка независимо проверяет допустимость `issues: opened`, затем использует существующий `github-reader` с read/glob/skill. Модель не получает shell, запись или помощник трекера. App/OIDC публикует ответ по существующему маршруту; новые права не добавляются.
- README, документы GitHub-агента, меток и workflow описывают фильтры и границы. Приложение, контракт, существующие снимки и workflow Hexlet не меняются.

## Проверки

Разовые проверки самой authorize-функции: владелец допускается; type:task/type:spec, чужие авторы/actor/repository/event отклоняются. Проверка режима reader и отсутствия прав записи. Полный существующий `mise run check`, независимые Standards/Spec. Постоянные автотесты не добавляются.

После merge обязательны новое обращение от владельца с содержательным ответом и подготовленный тикет с type:task при создании с явным skipped-run. До этих свидетельств #14 остаётся открытым. Поле темы не реализуется.
