## Критерии приёмки

- AC1: отслеживаемые файлы приложения перенесены из указанного SHA; исходный проект сохранён.
- AC2: исходный `.github/workflows/hexlet-check.yml` проекта 387 сохранён побайтно; перенесены `app-check` и `release-please`.
- AC3: новые задачи и команды GitHub направлены в репозиторий 387; исторические URL, ADR, словарь и снимки планов сохранены.
- AC4: README содержит адрес стенда предыдущего проекта, его границу версии и команды локального запуска; происхождение приложения документировано.
- AC5: release-please использует базовый SHA нового репозитория; существующая проверка выпуска использует эту границу.
- AC6: полный `mise run check` проходит без добавления новых тестов.
- AC7: ветка `chore/import-calendar` опубликована с Conventional Commits; результаты `app-check` и `hexlet-check` текущего SHA проверены в GitHub.

## Testing Decisions

Новые тесты не добавляются. Используются существующие Vitest, Playwright, линтер,
форматирование, типы, сборка, API generation check, release dry-run и hk validate.
Дополнительно сверяются хеши перенесённых файлов, защищённого workflow и локальные
ссылки документации. Самопроверки достаточно: бизнес-логика и API не меняются.

## Публикация и границы

Пользователь поручил перенос, затем явно разрешил коммит и push подготовленной ветки.
PR, merge в `main`, изменение прав Actions, новый deploy и завершение шага Hexlet
не входят в эту команду. Issue остаётся открытым до интеграции в `main`.
